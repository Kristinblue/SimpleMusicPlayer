# A、B 的函数分工

界面在 `src/main.cpp`；A 写 `src/data.c`，B 写 `src/player.c`。
`src/data.c` 已实现 A 的 8 个接口；`src/player.c` 已实现 B 的 17 个接口，界面已调用这两个模块。
启动时读取歌单、恢复收藏并初始化播放列表。点击歌曲行的爱心增删并保存收藏；播放按钮调用真实播放、暂停和继续，进度与时长定时从 B 查询。
收藏状态的查询、增删、去重和保存全部由 A 实现；界面只负责接收结果、显示红心和刷新列表。

## 先统一这些约定

- 共用 `include/song.h` 中的 `Song`，不要各写一套结构。
- `id` 是唯一的正整数歌曲编号，和数组下标是两回事。
- 字符数组使用 UTF-8，必须以 `\0` 结尾；`path` 是 WAV 文件路径。
- 函数只处理数据或音频，不使用 Qt，不用 `scanf`，错误返回给界面显示。
- 一般操作返回 `0` 表示成功、`-1` 表示失败；数量、布尔值、歌曲 ID 的返回规则见下表。
- 不要求你们安装 Qt。可用原来的编译器和自己的测试入口测试；交付时只给模块 `.c` / `.h`，不要把测试 `main()` 放进工程的 `src`。

## A：数据模块

准确的函数声明在 `include/data.h`，共 8 个函数。

| 函数 | 需要做什么 | 返回值 |
| --- | --- | --- |
| `data_load(song_file, favorite_file)` | 读取歌单和收藏编号，初始化模块内部数组；检查编号为正且不重复 | 0 / -1 |
| `data_get_songs(out, capacity)` | 把所有歌曲复制到调用者数组，不返回内部数组指针 | 数量 / -1 |
| `data_find_song(song_id, out)` | 按编号查询并复制一首歌曲；也承担编号存在性检查 | 0 / -1 |
| `data_get_favorites(out, capacity)` | 按歌单顺序复制已收藏的歌曲 | 数量 / -1 |
| `data_is_favorite(song_id)` | 查询是否收藏 | 1 是，0 否，-1 编号不存在 |
| `data_add_favorite(song_id)` | 添加收藏，防止重复；不存在的歌曲不能添加 | 0 / -1 |
| `data_remove_favorite(song_id)` | 取消收藏 | 0 / -1 |
| `data_save_favorites(favorite_file)` | 把当前收藏编号写入文件 | 0 / -1 |

建议第一版用定长数组，最多 `MAX_SONGS` 首。容量不足返回 -1，不越界、不静默截断。
已收藏的歌再次添加、未收藏的歌再次删除都返回 0；歌曲编号不存在则返回 -1。
首次运行没有收藏文件时按空收藏处理；损坏文件、打不开的歌单、重复编号应返回 -1。

建议统一一个简单的 UTF-8 文本格式：歌单每行 `编号|歌名|歌手|专辑|WAV路径`，收藏每行一个编号。例如：

```text
1|晴天|歌手A|夏日|music/01.wav
2|夜空|歌手B|夜航|music/02.wav
```

字段不能含 `|` 或换行。无效收藏编号忽略，重复收藏编号去重。保存收藏时先写临时文件，写成功再替换旧文件。
可先做读取、查询和编号检查，再做收藏与保存。

### A 模块实现与验证

- `src/data.c` 用定长歌曲数组和对应的收藏标记实现上述 8 个函数，不依赖 Qt。
- 读取支持 UTF-8 内容、文件开头的 BOM、LF/CRLF 和空行；歌曲字段不得为空或超过 `Song` 数组容量。收藏中的不存在编号忽略，非整数记录作为损坏文件报错。
- 加载先写入临时数组，全部成功后才替换当前数据，因此读取失败不会丢失原歌单与收藏。
- 保存先独占创建目标旁的 `.tmp` 文件，写入并关闭成功后再替换旧文件；Windows 使用 `MoveFileExA`，其他平台使用 `rename`。已有同名临时文件时返回 -1，保留该临时文件。
- 界面已接入 A：启动读取、查询收藏状态、显示收藏列表、点击爱心增删和保存。保存失败时撤销本次内存修改并提示，避免界面显示已收藏但文件没有保存。
- 原题的收藏夹“修改”尚未包含在这 8 个接口中，后续需要明确修改对象并补充接口与界面，不能将这部分视为已经完成。

## B：播放模块

准确的函数声明在 `include/player.h`，共 17 个函数。可使用 Windows MCI，工程已链接 `winmm`。

| 函数 | 需要做什么 | 返回值 |
| --- | --- | --- |
| `player_init()` | 初始化播放状态、默认顺序播放、默认音量 70 | 0 / -1 |
| `player_close()` | 关闭音频、释放资源；重复调用也安全 | 无 |
| `player_set_playlist(songs, count)` | 复制播放列表，保留编号和文件路径；不依赖 A 的内部变量 | 0 / -1 |
| `player_play(song_id)` | 按编号打开音频并从头播放；切换前关闭上一首 | 0 / -1 |
| `player_pause()` | 暂停并保留进度 | 0 / -1 |
| `player_resume()` | 从暂停位置继续 | 0 / -1 |
| `player_stop()` | 停止并把进度归零 | 0 / -1 |
| `player_previous()` | 按播放列表切到上一首并播放 | 新歌曲 ID / -1 |
| `player_next()` | 按播放列表切到下一首并播放 | 新歌曲 ID / -1 |
| `player_set_mode(mode)` | 设置顺序、列表循环或单曲循环 | 0 / -1 |
| `player_seek(position_ms)` | 跳到指定进度，检查范围 | 0 / -1 |
| `player_set_volume(volume)` | 设置 0~100 音量，切歌后保留 | 0 / -1 |
| `player_get_current_id()` | 查询当前歌曲 | ID；没有歌曲时 -1 |
| `player_get_position()` | 查询当前进度，单位毫秒 | 毫秒；没有歌曲时 0，失败 -1 |
| `player_get_duration()` | 查询总时长，单位毫秒 | 毫秒；没有歌曲时 0，失败 -1 |
| `player_get_state()` | 查询状态 | `PLAYER_STOPPED` / `PLAYER_PLAYING` / `PLAYER_PAUSED` |
| `player_update()` | 检测一首是否自然结束，按模式处理自动切歌 | 0 / -1 |

`player_update()` 由界面通过 `QTimer` 每 200 毫秒调用一次。B 不必自己写线程或 Qt 定时器。
顺序模式最后一首结束后停止；列表循环回到第一首；单曲循环重播当前歌曲。
手动上一首/下一首：顺序模式到边界返回 -1 并保持原状；两种循环模式可以首尾相接。
空列表、不存在的编号、无效音量/进度都不能越界访问。更换列表时停止旧播放并清空当前歌曲。
播放函数必须立即返回，不能写等待整首歌结束的循环，也不能用 `MCI_WAIT` 等待播放结束。

先实现初始化、播放、暂停、继续、停止；再补切歌、时长、进度、音量和循环。

## hyf负责界面接入

1. 启动：A 读文件 → 取歌曲数组和收藏状态 → 刷新列表；B 初始化 → 复制播放列表。
2. 收藏按钮：根据按钮所在行的歌曲调用 A 增删函数 → 保存成功后定时延后一轮事件处理，再刷新两侧列表，避免销毁正在执行点击事件的按钮。
3. 播放按钮：根据 B 的真实状态调用播放、暂停或继续，成功后更新图标。
4. 上一首/下一首：用 B 返回的歌曲 ID 查到对应数组下标，通过 `showSelectedSong()` 同步显示，不停止新歌；只有手动选择另一首时才由 `selectSong()` 停止旧歌。
5. 定时器：B 检测结束 → 读取真实歌曲 ID、状态、进度和时长 → 更新控件。拖动滑块时暂不覆盖它的位置。
6. 退出：调用 `player_close()`。读取失败、播放失败等提示统一由界面显示。
